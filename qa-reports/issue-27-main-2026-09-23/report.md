## Повторение

Нужны Git, Docker с Compose, Python 3 на хосте, свободный loopback-порт 18087 и браузер. Выполнять только в отдельном тестовом окружении. Секреты и рабочую БД не использовать.

```sh
mkdir /tmp/cq-acceptance-repeat
# Из checkout коммита, содержащего этот отчёт и scripts/acceptance/foundation.py:
git archive 3c98153199486dba5b4cde2f1dba9c04b05a13a5 | tar -x -C /tmp/cq-acceptance-repeat
python3 - <<'PY'
from pathlib import Path
p = Path('/tmp/cq-acceptance-repeat/docker-compose.yml')
p.write_text(p.read_text().replace('127.0.0.1:8080:80', '127.0.0.1:18087:80'))
PY
cp scripts/acceptance/foundation.py /tmp/cq-acceptance-repeat/foundation.py
shasum -a 256 /tmp/cq-acceptance-repeat/foundation.py
docker compose -p cq-acceptance-repeat -f /tmp/cq-acceptance-repeat/docker-compose.yml up --build -d --wait
python3 /tmp/cq-acceptance-repeat/foundation.py http://localhost:18087
docker compose -p cq-acceptance-repeat -f /tmp/cq-acceptance-repeat/docker-compose.yml restart
docker compose -p cq-acceptance-repeat -f /tmp/cq-acceptance-repeat/docker-compose.yml up -d --wait
curl --fail http://localhost:18087/api/health
docker compose -p cq-acceptance-repeat -f /tmp/cq-acceptance-repeat/docker-compose.yml exec -T api alembic current
```

Перед запуском сверить SHA-256 скопированного скрипта: `940d2f16fb770ddcf6dda641a99755a19f33b665e4ec71fa5cc2bbc4a8fee89d`. При несовпадении использовать версию скрипта из коммита этого отчёта.

Ожидается health с датой `2026-10-15` после рестарта. Скрипт запускается из checkout с этим отчётом; он использует только стандартную библиотеку, возвращает ненулевой код при несовпадении и намеренно оставляет дату-маркер. Для идентичного повторения используйте новый отдельный volume либо восстановите дату через оператора; исходное состояние скрипта — 1 октября.

Для UI: открыть origin, выбрать E0043, убедиться в истории, нажать кнопку имени для выхода. Один цикл — разогрев, затем 20 циклов с отдельным замером обоих действий до видимого заголовка. Точный алгоритм сохранён в [сценарии измерения](browser-timing.js), выполняемом в CUA REPL с привязанным `ptab`; это не самостоятельный Playwright runner.

Для будущего полного прогона: зафиксировать SHA интегрированного приложения, версии/хэши трёх новых профилей, исходное состояние и контрольные числа; выполнить строки протокола отдельно для browser/WebView; записать каждый UI-замер (≥20 после разогрева на каждом наборе/среде), все три холодных AI-запроса и fault/delay до 10 с. Приложить устройство/Android/WebView version, экраны клавиатуры, Back/Close, session expiry, внешней ссылки, поворота и offline. Не менять статусы без новых доказательств.

## Очистка

После повторения остановить только свой проект:

```sh
docker compose -p cq-acceptance-repeat -f /tmp/cq-acceptance-repeat/docker-compose.yml down
```

Команда сохраняет тестовый volume. Для полного удаления только этого одноразового тестового набора используйте ту же команду с `--volumes`, убедившись в имени проекта. Не применяйте её к рабочему проекту.

Только тестовый проект остановлен после сбора свидетельств; его volume сохранён с маркером даты для повторной проверки. Существующий демо-проект и пользовательские данные не затрагивались. Новых профилей и рабочих результатов не создавали; сессии тестовых логинов остаются только в изолированной БД. В доказательства не выводились cookie, токены, секреты или реальные персональные данные.

Текстовые логи сохранены с нормализацией концов строк и удалением завершающих пробелов; значения и строки результатов не изменены.
