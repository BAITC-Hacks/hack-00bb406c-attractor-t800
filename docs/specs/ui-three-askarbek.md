# Заменить текущий веб-интерфейс UI из ui-three-askarbek

## Problem Statement

Работающий Career Quest использует текущий веб-интерфейс, хотя желаемый UI находится в ветке `ui-three-askarbek`. Пользователь хочет видеть этот интерфейс в основном приложении, без отдельного запуска прототипа и без потери уже работающих сценариев.

## Solution

Сделать Halyk «Мой рост» из указанной ветки основным интерфейсом приложения. Перенести его визуальное оформление, изображения деревьев, структуру экранов и навигацию в существующий веб-клиент. Подключить доступные данные к действующему API и сохранить запуск через Docker Compose.

Вариант A («Живое дерево») предлагается как исходный вариант, поскольку он является вариантом по умолчанию в прототипе; пользователь отдельно не выбирал между A/B/C. Возможности, существующие только в прототипе, должны быть явно обозначены как демонстрационные или недоступные, без имитации сохранения в основном приложении.

## User Stories

1. Как пользователь, я хочу открывать новый UI по основному адресу приложения, чтобы не запускать отдельный прототип.
2. Как сотрудник, я хочу видеть оформление Halyk «Мой рост» из выбранной ветки, чтобы пользоваться согласованным визуальным направлением.
3. Как сотрудник, я хочу находить свою синтетическую учётную запись по ID, имени, роли или подразделению, чтобы войти в свой профиль.
4. Как сотрудник, я хочу сохранять сессию после обновления страницы, чтобы не выбирать аккаунт повторно.
5. Как сотрудник, я хочу выходить из аккаунта, чтобы безопасно переключиться на другого сотрудника.
6. Как сотрудник, я хочу входить в «Мой рост» через карточку сервиса, чтобы навигация соответствовала прототипу.
7. Как сотрудник, я хочу видеть вкладки «Дерево», «Тесты», «Цели», «Профиль» и «Halyk», чтобы ориентироваться в мини-приложении.
8. Как сотрудник, я хочу возвращаться на оболочку Halyk через одноимённую вкладку, чтобы понимать, как выйти из мини-приложения.
9. Как сотрудник, я хочу видеть дерево и его визуальные элементы из прототипа, чтобы новый дизайн сохранял характер исходного UI.
10. Как сотрудник, я хочу видеть свои фактические имя, роль, грейд и подразделение, чтобы прототипные персонажи не подменяли мой профиль.
11. Как сотрудник, я хочу видеть карьерную цель из серверного профиля, чтобы понимать направление развития.
12. Как сотрудник без карьерной цели, я хочу видеть понятное пустое состояние, чтобы отсутствие данных не выглядело ошибкой.
13. Как сотрудник, я хочу видеть навыки, текущие уровни и требования роли, чтобы оценить исходное состояние.
14. Как сотрудник, я хочу видеть историю активностей и их статусы, чтобы сохранить доступ к существующим данным.
15. Как сотрудник, я хочу видеть дату демонстрации, чтобы понимать временной контекст профиля.
16. Как сотрудник, я хочу различать работающие функции и демонстрационные экраны, чтобы не принять фиктивные XP, тесты или изменения цели за сохранённый результат.
17. Как пользователь, я хочу видеть состояния загрузки, ошибки и отсутствия данных, чтобы понимать результат действия.
18. Как пользователь телефона, я хочу пользоваться экраном и нижней навигацией без горизонтальной прокрутки, чтобы все действия оставались доступны.
19. Как пользователь компьютера, я хочу удобную адаптацию нового UI к широкому экрану, чтобы не терять читаемость и доступ к управлению.
20. Как пользователь клавиатуры, я хочу доступные названия элементов и видимый фокус, чтобы перемещаться по основным сценариям.
21. Как оператор, я хочу менять и сбрасывать дату демонстрации, чтобы сохранить существующий демонстрационный сценарий.
22. Как сотрудник, я хочу иметь доступ только к собственным данным, чтобы смена UI не ослабляла серверные ограничения.
23. Как проверяющий, я хочу запускать приложение прежней командой Docker Compose, чтобы замена интерфейса не требовала отдельного сервера прототипа.
24. Как проверяющий, я хочу видеть одинаковые серверные данные до и после перезапуска, чтобы убедиться, что UI не заменил базу моками.

## Implementation Decisions

- Источник UI — удалённая ветка `origin/ui-three-askarbek`, изученная на коммите с коротким идентификатором `5153f90`. Перед реализацией зафиксировать полный SHA используемой версии.
- Перенести UI в существующий модуль веб-клиента React/Vite, сохранив nginx, FastAPI, PostgreSQL и текущую схему развёртывания. Не заменять приложение целиком содержимым старой ветки.
- Перенести оформление, локальные изображения деревьев, оболочку Halyk и структуру мини-приложения. Банковская оболочка остаётся демонстрационной: реальные банковские операции не добавляются.
- Использовать вариант A по умолчанию как явно записанное предположение. Варианты B/C и панель разработчика не являются обязательной частью основного интерфейса.
- Сохранить серверные сценарии поиска аккаунтов, входа, выхода, восстановления сессии, собственного профиля и управления датой оператором.
- Отображать данные выбранного сотрудника из действующего API. Прототипные персонажи, балансы и уровни не должны подменять официальные данные.
- Не изменять модель авторизации и не доверять клиентскому переключателю ролей. Демонстрационное подтверждение руководителя не становится правом сотрудника.
- Сохранять доступ к навыкам и истории в новом профиле; явно обозначать ограничение числа показанных записей, если оно сохраняется.
- Для полей дерева, XP, стажа или расчётных показателей без подтверждённого источника показывать отсутствие данных либо явную демонстрационную маркировку. Не выводить их из несвязанных полей и не придумывать правила расчёта.
- Экраны тестов и целей сохраняют место в навигации. Действия без существующей серверной поддержки показывают понятный статус недоступности; не обещают сохранение или начисление XP.
- Перенос отдельной лаборатории генерации AI-тестов и её локального Node-сервера в основной продукт не включён в эту замену UI.
- Сохранить текущие API-контракты и базу данных. Новые доменные API и миграции не требуются для данной задачи.
- Изолировать состояние выбранного пользователя: выход и смена аккаунта не должны оставлять в интерфейсе данные предыдущего сотрудника.
- Обновить инструкции запуска и проверки по фактическому результату переноса.

## Testing Decisions

- Согласованная пользователем основная граница проверки — работающий веб-интерфейс через браузер, с настоящими nginx, API и тестовой базой.
- Проверять внешнее поведение: отображаемые данные, переходы, результаты действий, сохранение сессии и даты. Не привязывать тесты к внутренним React-компонентам или именам CSS-классов.
- Пройти единый сквозной маршрут: найти сотрудника → войти → открыть «Мой рост» → просмотреть дерево, цель, профиль, навыки и историю → вернуться в Halyk → обновить страницу → выйти → выбрать другого сотрудника.
- Отдельная ветвь этого маршрута для оператора: изменить дату → проверить её у сотрудника → сбросить дату → проверить сохранение после перезапуска.
- Проверить отсутствие цели, пустые разделы, загрузку, отказ API и истечение сессии. Не показывать успешный результат при неуспешном запросе.
- Проверить внешний вид на мобильном размере 390 × 844 и широком экране, доступность нижней навигации, отсутствие переполнения и загрузку всех локальных изображений. Сравнить основные экраны с вариантом A исходного прототипа.
- Повторно использовать существующий приёмочный HTTP-сценарий foundation для серверных регрессий: сессии, профиль, ограничения доступа и дата. Не создавать новую внутреннюю тестовую границу для переноса оформления.
- Предшествующий опыт — протокол приёмки foundation, сохранённые QA-отчёты и браузерные сценарии, описанные в прототипе. Тесты генерации AI относятся к отдельной лаборатории и сами по себе не подтверждают интеграцию нового UI.
- Критерий приёмки: основной адрес показывает новый интерфейс, существующие рабочие сценарии проходят на серверных данных, прототипные возможности обозначены честно, сборка веб-клиента и запуск Compose воспроизводимы.

## Out of Scope

- Реализация новых бизнес-функций XP, расчётных уровней, рекомендаций, прохождения и генерации тестов, редактирования целей, Jira, встреч и подтверждений руководителя.
- Реальные банковские операции и интеграция с Halyk.
- Новые рабочие места HR, руководителя и аналитика, производственная аутентификация и Android-приложение.
- Переработка официального набора данных, схемы БД или текущих контрактов API.
- Полное слияние ветки прототипа со всеми её историческими изменениями.

## Further Notes

Запрос пользователя: «в ветке ui-three-askarbek нужно использовать ui из этой ветки в проекте заместо web текущего».

Задача касается замены интерфейса, а не автоматического превращения всех моковых возможностей прототипа в серверные функции. Пользователь вызвал `to-spec`; реализация кода в рамках подготовки этой спецификации не выполняется.

Трекер проекта — GitHub Issues репозитория BAITC-Hacks/hack-00bb406c-attractor-t800. Спецификация согласована пользователем для публикации с меткой `ready-for-agent`.
