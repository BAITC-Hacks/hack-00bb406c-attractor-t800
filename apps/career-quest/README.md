# Career Quest — работающий прототип дерева навыков

Адаптивный React-интерфейс дерева навыков для сотрудника, руководителя и HR. Отдельное демо в ветке `demo-test-ui`, без подключения к приложениям `web/` и `api/`. Инструкция от клонирования до запуска: [RUN_DEMO.md](../../RUN_DEMO.md).

## Что можно попробовать

1. Нажать любую ветвь: открыть навык, оценку и дату подтверждения.
2. Открыть каталог: must-have для текущей профессии, поиск, категории и девять полноценных демонстрационных тестов.
3. Пройти System Design. При результате от 80/100 появляется шестая золотая ветвь. Ниже порога дерево не меняется.
4. Попробовать другой тест: одна отправленная попытка на сотрудника за календарный месяц. Выход до отправки не расходует попытку.
5. Переключить роль сверху: руководитель видит трёх прямых подчинённых, HR — девять профилей трёх отделов. Оценки общие для всех представлений; фильтры пересчитывают показатели. Есть поиск, сортировка, детали дерева и выгрузка CSV.
6. Открыть советника, сохранить чек-лист подготовки, выбрать карьерную цель, добавить или удалить встречу в личном плане. В профиле доступны результаты и достижения, в том числе на мобильном.
7. Нажать дату «Демо»: сменить роль, перейти к следующему месяцу или сбросить демонстрацию.

Прогресс сохраняется в localStorage текущего браузера: оценки, навыки, цель, подготовка и личные встречи. Сброс восстанавливает исходные примеры.

## Правила демонстрации

- Один тест **всего**, на выбор, в календарный месяц; не один тест каждого типа.
- Отправка, включая неуспех, расходует попытку. Просмотр и прерванный тест — нет.
- Пять вопросов, равный вес, порог 80/100. Правила и вопросы демонстрационные, требуют согласования с банком.
- Дерево содержит только подтверждённые навыки. Повторное подтверждение не создаёт дубль. Лучший результат сохраняет свою дату; все попытки остаются в истории.
- 100 демонстрационных XP за уникальный подтверждённый навык. Повторная сдача не даёт дополнительных XP.
- Категории и сложность теста не являются должностным грейдом. Тесты и XP не рассчитывают ОТК и не присваивают повышение.

## Запуск

Нужен Node.js 24 и npm. Из этой папки:

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 5183
```

Проверки:

```sh
npm test
npm run test:sites
npm run build
```

## Устройство

- `src/domain.js` — чистые функции оценки, месячной квоты, областей просмотра и восстановления данных; синтетические профили и банк тестов.
- `tests/domain.test.mjs` — проверки переходов состояния и повреждённых сохранений.
- `src/App.jsx` — сценарии сотрудника, каталог, результаты, профиль, локальная демонстрация интеграций.
- `src/SkillTree.jsx` — растровое дерево с масками, подтверждёнными узлами, анимацией и листовым представлением. Шесть основных графических ветвей; оставшиеся навыки демо-каталога добавляют побеги к кроне.
- `src/Assessment.jsx` — диалог оценки с вопросами, прогрессом, клавиатурной навигацией и подтверждением выхода.
- `src/PeopleView.jsx` — кабинеты руководителя и HR с расчётами по фактической выборке.
- `public/assets` — дерево из согласованного референса, производный вариант до золотой ветви и элементы бренда. Иконки Lucide скопированы с ISC-лицензией в `src/icons/LICENSE`.
- `scripts`, `worker`, `.openai/hosting.json` — подготовка статической сборки и вспомогательный обработчик раздачи; локальный запуск не требует облачного аккаунта.

## Граница готовности

Это рабочий локальный UI-прототип, не банковский production-сервис. Банк тестов и профили синтетические. Советник использует объяснимые правила, без LLM. Подключений к HRIS, LMS, календарю и Halyk SuperApp нет; кнопка Halyk показывает состояние возврата. Встречи не рассылают приглашения. Переключатель ролей демонстрирует области просмотра, не обеспечивает серверную авторизацию. Данные не синхронизируются между устройствами или вкладками в реальном времени.

Для реального пилота: серверная аутентификация и RBAC, хранение оценок и ответов на сервере, транзакционная квота `(employee_id, month)`, серверный подсчёт, версия теста/критериев, согласованная модель подтверждения, реальные HR/LMS и bridge супераппа. Переносить клиентскую проверку ответов как защиту в production нельзя.

Реализация изолирована в `apps/career-quest`; исходные приложения команды запускаются отдельно по инструкции в корневом README.
